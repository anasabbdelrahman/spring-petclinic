Method
------
Every case is a JSON payload with the structure Claude Code sends to a
PreToolUse hook for a Bash tool call, piped to the hook on stdin:

  {"session_id":"<session-id>","transcript_path":"<transcript-path>",
   "cwd":"<project-dir>","permission_mode":"default",
   "hook_event_name":"PreToolUse","tool_name":"Bash",
   "tool_input":{"command":"<command under test>","description":"guard-git test"},
   "tool_use_id":"<tool-use-id>"}

  printf '%s' "$payload" | .claude/hooks/guard-git.sh
  echo "exit: $?"

No command under test was executed. Each one exists only as a JSON string;
no Git command ran against the repository and nothing was pushed.
Session ids and local paths are replaced by <placeholders>; nothing else is
edited.

Exit codes: 0 = allowed by the hook (permissions still apply);
            2 = blocked, stderr is returned to Claude as the reason.

4. Incidental live refusal in the authoring session
---------------------------------------------------
After the hook was registered in .claude/settings.json, the agent's own
Bash call that assembled this file contained the literal text
`git push origin main --force` inside a heredoc (documentation text, not a
push). Claude Code ran the hook on that call and refused it before the
shell started; nothing ran. The complete error, as received:

  PreToolUse:Bash hook error: ["$CLAUDE_PROJECT_DIR"/.claude/hooks/guard-git.sh]: guard-git: refused force push (--force). Destructive Git operations need a human.

This shows two things: the registration is live in a real session, and the
hook fails closed on text that only mentions a dangerous form (see the
false-positive note in agent-controls-2026-09.md). The file was then built
with the static text written by the Write tool instead.
